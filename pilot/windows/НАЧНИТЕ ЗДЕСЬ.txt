DADO HOME — ТЕСТОВЫЙ КОМПЛЕКТ ДЛЯ WINDOWS x64

1. Распакуйте весь архив в обычную папку, например C:\Dado-Home-Pilot.
   Не запускайте изнутри ZIP, из Program Files или с сетевого диска.
   Весь путь должен быть без русских букв (ограничение PostgreSQL).
   Если имя пользователя Windows на русском, выберите C:\Dado-Home-Pilot.
2. Дважды нажмите «Запустить.cmd».
3. Дождитесь открытия http://127.0.0.1:5088 в браузере.
4. Нажмите «Доступы.cmd»: откроются тестовые логины и пароли.
5. Для кассы войдите как Кассир; для управления товарами — Администратор.
6. После работы нажмите «Остановить.cmd». Данные сохранятся.

УСТАНОВКА
В комплекте уже есть база PostgreSQL, backend и готовая панель.
Node, .NET SDK, Docker и интернет для обычного запуска не нужны.
Нужна Windows 10/11 x64. Первый запуск обычно занимает до минуты.
Папка должна быть доступна вашему пользователю для записи.
Если не установлен Microsoft Visual C++ Runtime, программа попросит один раз
запустить prerequisites\VC_redist.x64.exe (официальный установщик Microsoft).
Он включён в архив; установка может запросить права администратора.

ТЕСТОВЫЕ РОЛИ
+992900000001 — Администратор: все функции POS и управление сотрудниками.
+992900000002 — Кассир: продажи, отложенные и свои чеки, возврат по своим чекам.
+992900000003 — Финансы: чеки/отчёт POS, без проведения продаж и возвратов POS.
+992900000004 — Менеджер заказов: интернет-заказы, без POS.
+992900000005 — Поддержка: без POS.
Пароли уникальны для этой папки и создаются при первом запуске.
Они записаны в runtime\Access.txt; не публикуйте папку runtime.

ЧТО ПРОВЕРИТЬ ЗА 10 МИНУТ
1. Кассир → Касса → добавить 2 кружки по 35 с.; принять 100 с.
   Итого 70 с., сдача 30 с.; после продажи остаток кружек 13 вместо 15.
2. Откройте чек, нажмите «Печать»; выберите печать в PDF при отсутствии принтера.
3. Верните 1 кружку: возврат 35 с., остаток 14; нельзя вернуть больше проданного.
4. Добавьте полотенце, отложите чек. Откройте «Отложенные чеки» → «Продолжить».
   Остаток меняется только после проведения продажи.
5. Попробуйте продать товар «Последняя ваза»: в наличии только 1 штука.
6. Выйдите, войдите как Финансы: чеки и отчёт видны, кнопок продажи нет.
7. Войдите как Менеджер заказов и Поддержка: раздел POS отсутствует.
8. Остановите и снова запустите комплект: чеки и изменённые остатки сохраняются.

ВАЖНО О ТЕСТОВОМ РЕЖИМЕ
Деньги не списываются. Card/QR — только фиксация уже подтверждённой оплаты;
банковский терминал не подключён. Возврат денег также выполняется вне программы.
Печать — товарный чек, не фискальный. Отчёт использует сутки UTC.
Каталог содержит 8 демонстрационных товаров, не реальный склад.
Модуль POS и существующая веб-панель готовы для проверки.
Мобильный Flutter-клиент включён в исходники, но APK/iOS-сборка в комплект не входит.
Пункты старой панели с надписью «Модуль готовится к подключению» ещё не реализованы.

ГДЕ ДАННЫЕ
runtime\pgdata — локальная база с чеками, остатками и сотрудниками.
runtime\settings.json — порты и локальные ключи/пароли.
runtime\Access.txt — исходные тестовые доступы (после смены пароля не обновляется).
runtime\logs — журнал запуска и ошибок.
Все службы слушают только этот компьютер (127.0.0.1), не локальную сеть.

КОПИЯ И НОВЫЙ ТЕСТ
Сначала нажмите «Остановить.cmd», затем скопируйте всю папку комплекта.
Для чистого теста распакуйте исходный архив в новую папку; старые данные сохранятся.
Два комплекта с одинаковыми портами одновременно запускать нельзя.
Для смены портов остановите комплект и измените WebPort/DatabasePort в settings.json.

ЕСЛИ НЕ ЗАПУСКАЕТСЯ
Не закрывайте окно с ошибкой: в нём указана причина.
«Порт занят»: остановите другой экземпляр комплекта либо измените порты.
Если браузер не открылся автоматически, откройте адрес вручную.
Подробности — runtime\logs. Перед отправкой журналов проверьте их содержимое.
Не удаляйте runtime/settings.json отдельно от базы: в нём пароль к вашей базе.

Версии компонентов: build-info.json. Решения по POS: docs\POS.md.
