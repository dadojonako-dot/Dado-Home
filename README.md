# Dado Home

## Тестовый комплект Windows

Готовый комплект запускается из папки: **Запустить.cmd** → **Доступы.cmd** → вход в браузере. Остановка: **Остановить.cmd**. В комплект входят backend, веб-панель с POS, PostgreSQL и самодостаточный runtime .NET; среда разработки не требуется. Чеки и остатки сохраняются между запусками. Пароли пяти тестовых ролей генерируются локально, 8 демонстрационных товаров создаются один раз.

Сборка комплекта и повторение тестов: [pilot/README.md](pilot/README.md). Сценарий ручной проверки: [НАЧНИТЕ ЗДЕСЬ.txt](pilot/windows/НАЧНИТЕ%20ЗДЕСЬ.txt). Архитектура кассы и RBAC: [docs/POS.md](docs/POS.md).

Мобильные исходники Flutter включены в репозиторий; APK/iOS-приложение в Windows-комплект не входит. Банковский терминал и фискальный регистратор не подключены.

Отдельный проект клиентского мобильного приложения «ДАДО» для продажи одежды, обуви, аксессуаров, товаров для дома и «1000 мелочей».

## MVP
- Flutter: iOS + Android
- Каталог, поиск, размеры, цвета
- Корзина и оформление заказа
- Доставка / самовывоз
- Личный кабинет
- Двухуровневая авторизация (OTP/2FA)
- DADO Wallet
- Эквайринг, карты и QR-оплата
- Бонусная программа
- Заказы и отслеживание

## База данных и миграции
Backend использует PostgreSQL и EF Core migrations.

Начальная migration находится в `backend/DadoHome.Api/Migrations/20260923110000_InitialCreate.cs`.

При старте backend сначала выполняет `Database.Migrate()`, поэтому на чистой базе PostgreSQL схема создаётся автоматически до запуска фоновой обработки резервов заказов и до создания первого администратора.

Для существующей базы, созданной ранее вручную, перед включением этой baseline migration необходимо сначала сделать резервную копию и сверить текущую схему. Baseline рассчитана прежде всего на новую чистую базу.

## Первый администратор

При самостоятельном запуске обязательно задайте `ConnectionStrings__DadoDb` и случайный `Jwt__Key` длиной не менее 32 байт. Демонстрационные ключи отклоняются. Windows-комплект создаёт конфигурацию сам. Правила входа и оставшиеся ограничения production описаны в [docs/SECURITY.md](docs/SECURITY.md).
Первый администратор создаётся backend автоматически только если таблица сотрудников ещё пуста и заданы переменные окружения:

- `BootstrapAdmin__Name`
- `BootstrapAdmin__Phone`
- `BootstrapAdmin__Password`

Пример для локального запуска:

```bash
BootstrapAdmin__Name="DADO Admin" \
BootstrapAdmin__Phone="+992XXXXXXXXX" \
BootstrapAdmin__Password="CHANGE_ME_STRONG_PASSWORD" \
dotnet run --project backend/DadoHome.Api
```

Пароль не должен храниться в GitHub, `appsettings.json` или исходном коде. После создания первого администратора последующих сотрудников следует создавать через раздел **Сотрудники** в админ-панели.

Доступные роли:
- Администратор
- Менеджер заказов
- Финансы
- Служба поддержки
- Кассир (касса и свои чеки)

Система запрещает отключить себя и запрещает удалить/понизить последнего активного администратора.

## Payment security
PAN/CVV банковских карт не хранятся в DADO. Используется токенизация платежного провайдера; финальный статус оплаты подтверждается backend через webhook/API.
